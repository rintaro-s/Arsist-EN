# 手とコントローラーを空間に描く — `quest-hands`

パススルーで見えている本物の手やコントローラーは、何もしないと**どんな仮想の物よりも後ろ**に見えます
(仮想の物はパススルーの映像の上に描かれるため)。机の上の問題やキャラクターに手を伸ばすと、手が板の裏に回ったように見えます。

この拡張機能は、追跡している手と Touch コントローラーを 3D の空間に置きます。手より奥の仮想の物は手に隠れ、手前の物は手の上に出ます。

| 見え方 | 何が見えるか |
|---|---|
| 仮想 (`virtual`、既定) | 関節から作った手 (やわらかい白・肌色・青いガラス風) と、Meta の SDK のコントローラーの模型 (Quest 3 の Touch Plus など、ボタンも動く) |
| 本物 (`real`) | パススルーの自分の手とコントローラー。形は深度にだけ置く (色は描かない) ので、奥の仮想の物だけが隠れる |
| 使わない (`off`) | 今までどおり |

視界の表示 (HUD) は、どちらでもいつも一番手前です。

## どこで動くか

`requires`: `cap:hand-tracking` `cap:controllers` `sdk:meta-core` — Meta Quest のビルドにだけ入ります。ほかの端末では何もしません。
手は Unity の XR Hands (26 関節)、コントローラーの位置は Unity の XR 入力 (grip) から読みます (quest-input と同じ)。quest-input が無くても動きます。

## 使い方

拡張機能タブで有効にするだけです。見え方・手・コントローラー・手の色は設定で変えられます。

## スクリプト

```js
handVisuals.look();             // 今の見え方: 'virtual' / 'real' / 'off'
handVisuals.look('real');       // パススルーの本物の手を見せる (前後は正しいまま)
handVisuals.showHands(false);   // 手を出さない
handVisuals.showControllers(true);
```

## 設定

| キー | 既定 | |
|---|---|---|
| `look` | `virtual` | 見え方 (`virtual` / `real` / `off`) |
| `hands` | `true` | 手を出す |
| `controllers` | `true` | コントローラーを出す |
| `handColor` | `soft` | 仮想の手の色 (`soft` / `skin` / `glass`) |

## 仕組み

- **手**: 関節の間をカプセルでつなぎ、手首から指の付け根までを板で埋めます (`Runtime/HandShape.cs`)。OpenXR の手のメッシュには頼らないので、関節が読めればどの手でも同じ形になります。当たり判定は持ちません (UI の指し示しや、つかめる物を邪魔しない)。
- **コントローラー**: ビルドが `OVRControllerPrefab` を左右 1 つずつシーンに置き (`Editor/QuestHandsBuildHook.cs`)、実行時に grip の位置に合わせます。模型が見つからなければ、握りと輪の簡単な形で代わりに描きます。
- **位置合わせ**: 描く直前 (`Application.onBeforeRender`) に最新の姿勢を読むので、手が遅れて付いてきません。
- **前後**: 仮想は不透明 (深度を書く) で描きます。本物は `Arsist/HandOccluder` で深度だけを書き (quest-room の家具の隠しと同じ作り)、パススルーの手がそのまま見えます。
