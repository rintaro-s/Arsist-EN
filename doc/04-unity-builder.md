# UnityBuilder — `src/main/unity/UnityBuilder.ts`

Extends `EventEmitter`. Orchestrates the full headless Unity build pipeline from IR to APK.

Both Layster profiles go through this one builder (`runUnityBuild` in `src/main/main.ts`):

- **Layster.Virtual** — the Build dialog calls `unity:build` with data generated by `UnityBridge`.
- **Layster.Spatial** — `spatial:build` (`src/main/layster/spatialIpc.ts`) or `node scripts/layster-build.mjs`
  validate `project.spatial.json` (`validate.ts`), lower it (`src/shared/layster/spatial/lower.ts` →
  manifest / scenes / ui / scripts + `spatialData`) and call the same `build()`. The builder itself does not know
  Spatial beyond writing `spatial.json` and reading the manifest's `requiresFeatures` (doc/19-layster.md §4.1).

## `build(config)` — Main Entry Point

```typescript
async build(config: UnityBuildConfig): Promise<BuildResult>
```

**`UnityBuildConfig`:**
```typescript
{
  projectPath: string          // the Unity WORK directory (callers pass <outputPath>/TempUnityProject); created if missing
  sourceProjectPath?: string   // the Arsist project root (Assets/ is synced from here)
  buildTarget: 'Android' | 'iOS' | 'Windows' | 'MacOS'   // only Android is used
  targetDevice: string         // adapter folder name under Adapters/
  outputPath: string
  developmentBuild: boolean
  manifestData: object         // generated by UnityBridge (Virtual) or lower.ts (Spatial)
  scenesData: object[]
  uiData: object[]
  scriptsData?: object
  spatialData?: object         // Layster.Spatial only → spatial.json
  unityVersion?: string
  unityPathOverride?: string
  buildTimeoutMinutes?: number // default 60
  logFilePath?: string         // default <outputPath>/unity_build.log
  cleanOutput?: boolean        // empty outputPath first (the work directory inside it is kept)
  manualLicenseFile?: string   // .ulf, imported in a separate Unity run before the build
  cleanBuild?: boolean         // discard the reusable Unity workspace and rebuild from scratch
}
```

**Return value:**
```typescript
{
  success: boolean
  outputPath?: string   // absolute path to .apk or .aab
  error?: string
}
```

## Build Phases

Progress phases (`emitProgress`) in order: `prepare` 0 → `prepare-unity` 5 → `prepare-jint` 8 → `transfer` 10 →
`patch` 30 → `sdk` 40 → `extensions` 42 → (`sdk-vrm` 45 → `sdk-vrm-protect` 48) → `build` 50–85 → `verify` 90 →
`complete` 100.

### Phase 1 — Validate (`prepare`, 0 %)

- `validate(config.unityVersion)` — Unity binary exists, version matches.
- Validates `manualLicenseFile` (if any) and imports it in a separate Unity run before the real build.
- `findIrProblems(config)` runs **before Unity is launched** and aborts the build on IR problems that would
  otherwise produce an APK that installs fine but is broken on device: a `canvas` object with no (or a dangling)
  `canvasSettings.layoutId`, an `Image` pointing at a file Unity cannot import as a texture (e.g. `.webp`), and an
  invalid `arSettings.backgroundMode` / `backgroundColor`. Each problem line carries its own fix instruction —
  by design there is no silent auto-repair.
- `planExtensions(config)` decides **device tags** (`adapter.json` + `sdk:*` from `detectSdkTags`), **features used**
  (`projectFeatureTags` plus the manifest's `requiresFeatures`, which `lower.ts` writes for Spatial projects) and the
  **extensions** that go into this build (enabled + device-providing ones whose `requires` the tags satisfy;
  the rest become `absentExtensions`), plus engine-part `replacements`. Unsupported features and character
  animation name mismatches are logged as warnings.

### Phase 2 — Prepare Unity Project (`prepare-unity`, 5 %)

- Resolves `UnityBackend/ArsistBuilder/` template (relative to the Arsist repo root or `process.resourcesPath`).
- **Reuses the working directory when possible** (see [Incremental workspace](#incremental-workspace) below) —
  the template is *synced*, not re-copied, so Unity's `Library/` survives between builds.
- Adds uGUI/TextMeshPro packages for the Unity version (`ensureUnityUiPackages`) and the Inference Engine package
  only when the project has models (`ensureInferencePackage`).

#### Incremental workspace

The working directory (`<outputPath>/TempUnityProject`) is **kept between builds**. Wiping it would force Unity
to re-import every asset, recompile all C#, and rerun IL2CPP + Gradle from scratch on every build — that was the
single biggest cause of long build times.

`prepareUnityProject()` writes a stamp file `.arsist-workspace.json` at the workspace root and rebuilds from
scratch only when one of these changes:

| Trigger | Why |
|---------|-----|
| `cleanBuild: true` in the build config | User asked for it (checkbox in the Build dialog) |
| Unity editor path changed | `Library/` is version-specific |
| Target device changed | Otherwise the previous device's SDK stays in `Packages/` |
| Template `ProjectSettings/**` or `Packages/manifest.json` changed | Those are *not* re-synced (the build mutates them) |
| `Library/` missing | Nothing to reuse |
| `WORKSPACE_CACHE_VERSION` bumped | Preparation logic changed |

Everything else is kept in sync by `syncDirectory()`:

- Change detection compares the **source** stamp (`size:mtimeMs`) against `.arsist-sync.json` recorded at the
  destination — *not* the destination's own mtime, because `preserveTimestamps` rounds sub-millisecond values
  and would report spurious changes every run.
- Unity-invisible directories (`Samples~`, `Tools~`, `Marker~`, `.git`) are skipped — this alone avoids copying
  ~110 MB of the XREAL SDK per build.
- `prune: 'mirror'` deletes destination files that vanished from the source, but **keeps Unity-generated `.meta`
  files** whose asset still exists (deleting them would reassign GUIDs and trigger a full re-import).

Regenerated unconditionally on every build (stale content would otherwise leak between projects/devices):
`Assets/Scenes/`, `Assets/Arsist/Editor/Adapters/`, and any `Assets/ArsistGenerated/*.json` not written this run.

### Phase 3 — Prepare Jint DLLs (`prepare-jint`, 8 %)

- Skipped when `Jint.dll` and `Acornima.dll` are already in `Assets/Plugins/`; removes a legacy `Esprima.dll`.
- Otherwise takes them from `Jint-*.nupkg` / `Acornima-*.nupkg` in `sdk/nupkg/` or downloads them.
- Resolution order: `netstandard2.1` → `netstandard2.0` → `net6.0` → recursive fallback search.

### Phase 4 — Transfer Data (`transfer`, 10 %)

`transferProjectData()` writes into `Assets/ArsistGenerated/`:
- `manifest.json` — manifest + `scenes`, plus build-time fields: `logRelay` (this PC's LAN address, see
  doc/13), `deviceTags`, `features`, `extensions`, `absentExtensions`, `replacements`
- `scenes.json` — scene objects array
- `ui_layouts.json` — UI layout array
- `dataflow.json` — DataFlow definition (if the manifest has `dataFlow`)
- `scripts.json` — script bundle (if `scriptsData` is present)
- `spatial.json` — Layster.Spatial runtime data (only if `spatialData` is present; read by `ArsistSpatialRuntime`, doc/20)

Any other `*.json` left there from a previous build is deleted. Also syncs `<sourceProjectPath>/Assets/` →
`Assets/ArsistProjectAssets/` (`prune: 'mirror'`).

### Phase 5 — Apply Device Patch (`patch`, 30 %)

Delegates to `applyDevicePatch(unityProjectPath, targetDevice)`:
1. Resolves the adapter directory via `src/main/adapters/adapterDirs.ts` (`Adapters/<device>/` or an extension's
   `Adapters/<name>/`). No match for a Quest/XREAL-looking name → a loud warning (permissions will be missing).
2. Applies `AndroidManifest.xml` (or `Manifest/AndroidManifest.xml`) to `Assets/Plugins/Android/`.
3. Copies `.cs` editor scripts (from `Scripts/`, `Editor/` or the adapter root) to `Assets/Arsist/Editor/Adapters/<device>/`.
4. Copies `Packages/` entries.
5. Always calls `ensureAndroidCleartextHttpPolicy()` to patch `android:usesCleartextTraffic="true"`.

### Phase 6 — Integrate Required SDKs (`sdk`, 40 %)

- **XREAL target** (`isXrealTarget`): copies `sdk/com.xreal.xr/package/` → `Packages/com.xreal.xr/`, adds `file:com.xreal.xr` to `manifest.json`, injects required Unity module dependencies (`com.unity.ugui`, `com.unity.textmeshpro`, etc.).
- **Quest target** (`isQuestTarget`): copies `sdk/quest/com.meta.xr.sdk.core-*.tgz` (and optionally mruk) into `Packages/`, updates `manifest.json`, applies Quest XR bootstrap assets from the sample project.

### Phase 7 — Extensions (`extensions`, 42 %) and VRM (`sdk-vrm`, 45–48 %)

- `stageExtensions()` copies each active extension's C# to `Assets/ArsistExtensions/<id>/`, writes the generated
  registry (`ArsistExtensionRegistry.g.cs`) and `link.xml`, merges Android manifest additions, stages
  `unity.packages`, `unity.unitypackages` and `unity.overrides`, and removes extensions that no longer apply (doc/17).
- `writeAndroidToolchainSettings()` writes `ProjectSettings/AndroidExternalToolsSettings.asset` (JDK / SDK / NDK) before Unity starts.
- If the project uses VRM and no extension replaces `vrm-loader`, imports the UniVRM 0.x `.unitypackage` from `sdk/`
  (skipped when already imported), warns about VRM 1.0 models, and adds VRM assemblies to `Assets/link.xml`.

### Phase 8 — Execute Build (`build`, 50–85 %)

Spawns Unity directly (no shell). Before that it checks for Gradle (`detectGradle`) and fails fast if none is found.

```
Unity.exe
  -batchmode -nographics -quit
  -projectPath <working-dir>
  -executeMethod Arsist.Builder.ArsistBuildPipeline.BuildFromCLI
  -buildTarget Android
  -outputPath <outputPath>
  -targetDevice <device>
  -developmentBuild true|false
  [-manualLicenseFile <ulf>]   (only on the retry that uses one)
  -arsist-jdk <jdk-path>
  -arsist-android-sdk <sdk-path>
  -logFile <log-file>
```

Environment variables injected: `HOME`, `JAVA_HOME`, `ANDROID_HOME`, `ANDROID_SDK_ROOT`, `PATH` (with JDK `/bin` prepended).

## Retry Logic

Only **licensing** failures trigger retries (detected by `isLicensingNoise()`: `Access token is unavailable`,
`Licensing::Module/Client`, `LicensingClient has failed validation`, pipe `IOException`, …). Real compilation errors
are returned immediately. If a fresh APK exists despite a licensing error, it is treated as success. The steps, each
only while the error is still licensing:

| Step | Strategy |
|------|---------|
| 1 | Default (`-batchmode -nographics`) |
| 2 | Same again after 10 s |
| 3 | Linux with `DISPLAY`: without `-nographics` |
| 4 | Windows: GUI (no `-batchmode` / `-nographics`) |
| 5 | Linux with `DISPLAY`: GUI, with the configured `.ulf` |
| 6 | Find a local `.ulf` (`getUnityLicenseCandidates`), import it, rebuild |
| 7 | If a `.ulf` was configured: retry without it (Unity Hub cache) |

Separately, `OpenXR Settings found in project but not yet loaded` triggers one plain rebuild. After all attempts,
`verifyBuildOutput()` runs regardless: a fresh output wins over a reported failure.

## APK Discovery — `verifyBuildOutput()`

Searches for the output APK in this order:
1. `<outputPath>/<basename(projectPath)>.apk`
2. `<outputPath>/<manifest.projectName>.apk`
3. `<outputPath>/build.apk`
4. `<outputPath>/ArsistApp.apk`
5. All `.apk` / `.aab` files in `outputPath`, newest-first
6. Recursive sub-directory search up to 5 levels deep, newest-first

Only files newer than the build start time (`sinceEpochMs`) are accepted.

## Android Toolchain Detection

### JDK — `detectJdkPath()`

Priority:
1. Unity bundled OpenJDK (`Editor/Data/PlaybackEngines/AndroidPlayer/OpenJDK/`)
2. `JAVA_HOME` environment variable
3. `JDK_HOME` environment variable

### Android SDK — `detectAndroidSdkPath()`

Priority:
1. Unity bundled SDK (`Editor/Data/PlaybackEngines/AndroidPlayer/SDK/`)
2. `ANDROID_HOME` / `ANDROID_SDK_ROOT` environment variables
3. `%LOCALAPPDATA%\Android\Sdk` (Windows) / `~/Library/Android/sdk` (macOS) / `~/Android/Sdk` (Linux)

On Windows only, if the detected SDK is under a protected root (Program Files) or is not writable, it is **mirrored** to `userData/android-sdk-cache/<unity-version>/<source-key>/` before being passed to Unity.

## Unity Log Parsing — `readUnityLogIssues()`

Reads the Unity log file line-by-line and classifies each line:

- **Error** — lines matching `(^|\s)error(\s|:)`, `Exception\s*:`, or `BuildFailedException:`
- **Warning** — lines matching `(^|\s)warning(\s|:)`
- **Licensing noise** — filtered out before error classification

`[Arsist] Build failed:` lines (from `ArsistBuildPipeline`) and `Scripts have compiler errors.` are always collected;
indented continuation lines (Gradle/AGP causes) are joined to the error line (`collectErrorMessage`).

`pickBestError()` (inside `executeUnityBuild`) prefers: `[Arsist] Build failed:` > C# compiler errors (`error CS\d+`) >
`BuildFailedException` / `Error building Player` > non-licensing errors > anything else. Exit code 0 counts as success
even when the log has errors.

---

## Windows Shell Compatibility — `ensureWindowsShellAvailability()`

On Windows, sets `ComSpec` if missing, searches for `powershell.exe` in PATH and common install locations (PowerShell 7, System32 WPS), then prepends its directory to `PATH`. This ensures Unity's internal build scripts can invoke PowerShell during `Expand-Archive` (nupkg extraction) and Gradle invocations.

---

## `validate(requiredVersion?)` — Pre-Build Check

1. Verifies the Unity binary exists.
2. Reads the version (`getUnityVersion()`).
3. Compares it against `requiredVersion` (if provided).
4. Returns `{ valid: boolean, version?: string, error?: string }`.

## 端末に入れる (adb)

ビルド画面の下に、つながっている端末が並ぶ (`adb devices -l`、`src/main/device/Adb.ts`)。
「ビルドしてインストール」はビルドの後そのまま入れ、「インストール」は今ビルドした APK を入れ直す。
(Virtual のビルド画面のみ。Layster.Spatial のビルド画面 `SpatialBuildDialog` は APK を作るだけ)

- adb は **Unity が同梱している Android SDK のもの**を優先して使う (別途入れなくてよい)。
  次に `ANDROID_HOME` / `ANDROID_SDK_ROOT`、最後に PATH (`getAdbCandidates`)。
- 端末が複数あれば選ぶ。`unauthorized` (端末側で許可待ち) や `offline` は選べず、理由をその場に出す。
- 入れるのは `adb -s <端末> install -r -d <apk>`。**必ず `-s` で端末を指定する** (1 台のときも)。
  指定を省くと、別の端末が繋がっていたときに、そちらへ入ってしまう。
- ここでするのは「並べる」と「このプロジェクトの APK を入れる」だけで、端末の他の状態には触らない。

## ダイアログの高さ

`.modal` は画面の高さ (`100vh - 3rem`) を超えない。頭と足は残り、中身だけが送られる
(`src/renderer/styles/globals.css`)。縦の狭いモニターだと、ビルド画面のように中身の長い
ダイアログが画面からはみ出し、下のボタンに手が届かなくなるため。
